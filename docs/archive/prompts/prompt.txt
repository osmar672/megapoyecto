# Sistema Bancario — Frontend JavaScript Puro

Desarrolla un proyecto Frontend educativo que simule un pequeño sistema bancario.

El proyecto debe ser **simple, funcional y fácil de entender**. No sobrearquitectures la solución.

## Tecnologías obligatorias

Utiliza únicamente:

* HTML5
* CSS3
* JavaScript puro
* Node.js
* npm
* ES Modules
* LocalStorage

NO utilizar:

* React
* Vue
* Angular
* TypeScript
* Express
* Base de datos
* Backend
* Firebase
* APIs externas

Node.js y npm se utilizarán únicamente para administrar el proyecto y ejecutar el entorno de desarrollo.

---

# 1. Estructura

Crear una estructura sencilla:

```text
sistema-bancario/
│
├── package.json
├── index.html
│
├── css/
│   └── style.css
│
├── js/
│   ├── main.js
│   ├── data.js
│   ├── auth.js
│   ├── clientes.js
│   └── storage.js
│
└── assets/
```

Utilizar `import` y `export` para trabajar con módulos.

# 2. Autenticación

Crear una pantalla de Login.

Campos:

* Usuario
* Contraseña

Crear un usuario administrador ficticio:

```text
Usuario: admin
Contraseña: 1234
```

Cuando las credenciales sean correctas:

```text
Login
   ↓
Dashboard
```

Si son incorrectas mostrar:

```text
Usuario o contraseña incorrectos
```

Guardar la sesión utilizando:

```javascript
localStorage
```

Por ejemplo:

```text
bank_session
```

Si existe una sesión activa, el usuario debe ingresar directamente al Dashboard.

Agregar botón:

```text
Cerrar sesión
```

Al cerrar sesión:

* Eliminar la sesión.
* Regresar al Login.

# 9. LocalStorage

No utilizar ninguna base de datos.

Utilizar:

```javascript
localStorage
```

para guardar los clientes.

Crear un módulo:

```text
js/storage.js
```

con funciones:

```javascript
saveClients()
getClients()
deleteClients()
```

Los datos deben mantenerse aunque el navegador se recargue.

# 11. Validaciones

Implementar validaciones básicas:

* Ningún campo obligatorio puede estar vacío.
* El correo debe tener formato válido.
* El saldo debe ser numérico.
* El saldo no puede ser negativo.
* La identificación no puede repetirse.
* El correo no puede repetirse.

Mostrar los errores directamente en el formulario.

```text

       ↓
```
