PROMPT 1 — BASE DE LA INTRANET ESCOLAR

CONTRATO CENTRAL DE INTEGRACIÓN — OBLIGATORIO PARA LAS 3 COMPUTADORAS

Este proyecto será desarrollado por separado en tres computadoras y después se unirán los resultados. Por esa razón, la compatibilidad entre módulos es una restricción obligatoria y tiene prioridad sobre cualquier preferencia de organización distinta.

1. ÚNICO ESPACIO GLOBAL PERMITIDO

Todos los scripts deben utilizar exclusivamente este objeto global compartido:

window.SCHOOL_INTRANET = window.SCHOOL_INTRANET || {};

Está PROHIBIDO crear otras variables, constantes o funciones globales propias del proyecto.

Cada etapa debe trabajar dentro de su propio módulo:

- Computadora 1 / Prompt 1: SCHOOL_INTRANET.modules.p1
- Computadora 2 / Prompt 2: SCHOOL_INTRANET.modules.p2
- Computadora 3 / Prompt 3: SCHOOL_INTRANET.modules.p3

Usar un IIFE, closure o estructura equivalente para que let, const, funciones auxiliares, selectores, cache DOM y estado interno queden encapsulados.

Ejemplo de patrón obligatorio:

(function (APP) {
    'use strict';
    APP.modules = APP.modules || {};
    APP.modules.pX = APP.modules.pX || {};
    const MODULE = APP.modules.pX;
    // Todo el código de esta etapa queda dentro de este scope.
})(window.SCHOOL_INTRANET = window.SCHOOL_INTRANET || {});

No declarar en el scope global nombres genéricos como:

- data
- users
- state
- currentUser
- init
- render
- save
- load
- modal
- notifications
- events
- config
- settings

2. PREFIJOS OBLIGATORIOS

Cada etapa tiene un prefijo exclusivo:

- Prompt 1: p1-
- Prompt 2: p2-
- Prompt 3: p3-

Aplicarlo a TODO elemento nuevo que pertenezca exclusivamente a esa etapa:

- id HTML: p1-login-form, p2-forum-modal, p3-stats-chart
- clases CSS: p1-card, p2-forum-post, p3-stat-card
- variables CSS: --p1-sidebar-width, --p2-forum-gap, --p3-chart-height
- data attributes: data-p1-action, data-p2-category, data-p3-filter
- nombres de animaciones CSS: p1-fade-in, p2-achievement-pop, p3-section-enter
- claves internas de cache o dataset no compartidas

Nunca utilizar IDs genéricos como #modal, #search, #dashboard, #form, #table o #content.

8. REGLAS DE FUNCIONES Y VARIABLES JAVASCRIPT

- Toda variable debe declararse explícitamente con const o let.
- Prohibido asignar variables sin declaración.
- Evitar var.
- No declarar dos funciones con el mismo nombre dentro del mismo módulo.
- Las funciones públicas deben vivir dentro del namespace de su módulo.
- Las funciones privadas deben permanecer dentro del closure.
- No sobrescribir APP.modules.p1, APP.modules.p2 o APP.modules.p3 completos si ya existen; extenderlos.
- No modificar prototypes nativos.
- No usar onclick inline en HTML; usar addEventListener.
- No depender de variables creadas accidentalmente por IDs HTML.

9. CSS SIN COLISIONES

- Prompt 1 puede definir tokens globales base bajo :root usando prefijo --app-*.
- Prompt 2 y Prompt 3 pueden consumir --app-* con fallback, pero NO redefinirlos globalmente.
- Prompt 2 solo crea variables --p2-*.
- Prompt 3 solo crea variables --p3-*.
- No usar selectores genéricos que afecten todo el proyecto como .card, .modal, .active, .hidden, .button, .container.
- Usar siempre el prefijo de la etapa, por ejemplo .p2-modal o .p3-active.
- Si se necesita una utilidad compartida existente de Prompt 1, reutilizarla sin redefinirla.

OBJETIVO

Crear la estructura principal de una intranet para un colegio público.

Debe ser una aplicación web moderna, profesional, responsive y fácil de utilizar.

No quiero únicamente diseño visual. Los botones, formularios, filtros, navegación y módulos deben funcionar.

- Logo del colegio

- Recuperar contraseña
- Botón Iniciar sesión

- Mensajes de error
- Loader al iniciar sesión

Agregar animaciones suaves:

- Entrada del formulario
- Animaciones en los campos
- Animación al iniciar sesión correctamente
- Transición desde el login hacia el dashboard

Agregar usuarios de demostración para diferentes roles:

- Administrador
- Docente
- Estudiante
- Familiar

- Sidebar
- Header

10. DATOS COMPARTIDOS

Los módulos NO deben funcionar aisladamente.

Ejemplo:

Si se crea un aviso:

1. Debe guardarse en LocalStorage.
2. Debe aparecer en Avisos.
3. Debe aparecer en Dashboard.
4. Debe generar una notificación.

Si un docente cambia una nota:

1. Debe guardarse.
2. El estudiante debe verla.
3. Debe generarse una notificación.

Centralizar los datos y evitar duplicación innecesaria.
